# 混音实验 V1：处理链与复用指南

**正式 V1 就是用户确认成功的实验 V13。** 发布时只整理命名、文件和记录，不重新处理或编码音频；正式音频应与对应 V13 文件逐字节一致，以发布清单中的 SHA-256 为准。旧实验编号保留，用于追溯，不再把 V13 当作需要继续修正的临时版本。

这份指南记录最终有效的处理路径。它既不是某位歌手实际使用的插件参数，也不是给任意未经处理的录音直接套用的万能 preset。

## 1. 先使用成品与分轨

正式成品是 `MUSIC_MIX_EXPERIMENT_V1.wav` / `.mp3`。分轨均以 `MUSIC_MIX_EXPERIMENT_V1_` 开头，48 kHz、24-bit PCM、双声道、214.27375 秒，从工程 0:00 开始。

| 分轨后缀 | 实际内容 | 用法 |
|---|---|---|
| `VOCAL.wav` | 母带前完整人声 | 与本版 BEAT 相加 |
| `VOCAL_CORE.wav` | 已修音、已处理的人声主体，含早先打印的空间和动态 | 与 FX 相加；不是原始干声 |
| `VOCAL_FX.wav` | V11 建立、V12/V13 调整后的合成衬层、回声、浅尾声和深尾声 | 控制新增制作层的整体电平 |
| `BEAT.wav` | 包含 V13 最新局部让位的伴奏 | 必须使用本版，不能换成 V9 或原始伴奏来精确重组 |

在 Ableton 以 48 kHz 工程导入，所有文件起点对齐 0:00、关闭 Warp、Clip Gain 与轨道推子设 0 dB、声像居中，关闭额外效果与发送。选择一种方式：

- 两轨方式：`VOCAL + BEAT`。
- 三轨方式：`VOCAL_CORE + VOCAL_FX + BEAT`。

不要同时播放 VOCAL 和 CORE/FX，否则会把人声重复叠加。上述结果是**母带前混音**；正式成品还经过总线增益和限幅，直接相加不应与正式成品等响。

V13 内部浮点源文件的 CORE + FX = VOCAL、VOCAL + BEAT = premaster 检查误差为零。独立导出的 24-bit 分轨各自经过量化，重新相加可能出现极低的量化差异；这与“V1 发布音频直接复制 V13、文件哈希相同”是两种不同的核验。

本次便携 ZIP 包含正式主 WAV/MP3、等响对照和经验资料；四份完整分轨在正式版本目录单独下载。ZIP 本身不是含全部分轨及源素材的 DAW 工程。

## 2. 最终真正使用的版本谱系

```text
用户导出的已修音/已混音人声
  → 早期对齐与空间整理
  → V4 清晰度与窄峰控制
  → V6 OPEN 低中频及已有空间整理
  → V7 轻微存在感调整
  → V11 人声美化与新的分层空间
  → V12 持续音、电平与空间细修
  → V13 与伴奏衔接、弱字及句头细修
  = 正式混音实验 V1

用户提供的伴奏
  → V4 频率整理与局部让位
  → V7 EQ 与原有 Side 展开
  → V9 中央动态让位
  → V13 更局部的中央让位
  = 正式 V1 BEAT
```

关键分支必须分清：

- V11 主唱直接回到 V7 人声。因此 V8 的持续制作层、V9 的新增人声低频整理和 V10 的重建人声音频，没有按编号顺序全部叠进 V1。V9 在最终版本里主要贡献伴奏。
- V10 被用户明确否定的音频方向没有重新引入。源码读取的 `/workspace/audio-v10-pitch/comparison.npz`，其中 `mixed`、`mixed_periodicity`、`t` 是**原已混音人声的音高/周期性统计与时间轴**，只用于挑选活动、持续元音及自动化控制，不是 V10 重建音频。
- 原 dry vocal 用于活动检测等分析控制，没有作为第二条可听干声叠在已修音主唱上。
- 《1 Call》只用于参考分析，参考歌曲、人声分离结果和模型权重均不属于成品，也不包含在发布包里。最终听到的新增衬层来自用户自己的人声。

## 3. 继承到 V1 的前段处理

这些环节已经打印进 CORE，不能通过静音 FX 撤销。下列参数用于解释来源，而不是要求在 V1 CORE 上再套一遍。

| 阶段 | 保留下来的处理 |
|---|---|
| V4 人声 | 从已对齐、已做空间准备的同一人声重新设置 EQ：65 Hz 二阶高通；180 Hz 低架 −1 dB；420 Hz/Q0.85/−2.2 dB；3 kHz/Q0.8/+2 dB；7 kHz 高架 −1.5 dB。另以 192 kHz 过采样、−8.5 dBFS ceiling、0.5 ms attack / 15 ms release 控制窄峰，之后配平电平。V4 替换早期 EQ，并非把 V3 的 EQ 原样再叠加一次。 |
| V6 OPEN | 525 Hz/Q1.25 固定 −1 dB，动态最多再 −2 dB；820 Hz/Q1.65 动态最多 −1.5 dB；1.5 kHz/Q0.85/+0.8 dB。动态控制约 25/150 ms。Side 的 650 Hz/Q0.65/−3.5 dB，Side 随活动乘 0.62–0.90；Mid 空隙最低乘 0.88，再做整体响度配平。采用 OPEN，没有采用更强的 DRIER。 |
| V7 人声 | 1.9 kHz/Q0.9/+0.6 dB；配平后约再前推 0.25 dB，无新增混响。 |
| V4 伴奏 | 120 Hz 低架 −0.8 dB；450 Hz/Q0.8/−1.5 dB；2.2 kHz/Q0.8/+2 dB；4.5 kHz 高架 +1 dB。唱歌时 2.5 kHz/Q1 最多 −0.8 dB，两个声部分别配平。 |
| V7 伴奏 | 260 Hz/Q0.85/−1.5 dB；1.8 kHz/Q0.8/+1 dB；6 kHz 高架 +2.5 dB。增强原本存在的 250 Hz 以上 Side，设计系数约对应 +5 dB 的高频增量，再匹配伴奏响度；过渡频带受滤波相位影响，不是精确的砖墙分频。 |
| V9 伴奏 | 只处理 Mid：800 Hz/Q0.8、最多 −2.5 dB；比较 600 Hz–2 kHz 人声与伴奏能量，并由活动控制，35 ms attack / 180 ms release。Side 在局部处理阶段保留，随后整条伴奏统一配平。 |

这些宽频段的处理是针对现有文件的操作选择，不是测出了唯一的房间共振。Mid/Side 也不等于直达声/混响分离。已有房间和旧插件染色不能据此宣称被完整移除。

早期说明与实现见 [V4](archive/vocal-v4/NOTES.md)、[V6](archive/vocal-v6/NOTES.md)、[V7](archive/vocal-v7/NOTES.md)、[V9](archive/vocal-v9/NOTES.md)。

## 4. V11–V13：形成最终认可方向的增量链

### 人声主体

| 环节 | 实际设置与作用 |
|---|---|
| V11 温和修饰 | 80 Hz 二阶高通；300 Hz/Q0.9/+0.4 dB；10 kHz 高架 +0.7 dB。900 Hz/Q1.8 动态最多 −0.8 dB，4 kHz/Q1.1 动态最多 −1 dB；仅相对突出时动作，20/120 ms，中位动作接近零。 |
| V11 谐波残差 | 220 Hz–2.4 kHz 送轻微非对称 tanh，4 倍过采样，去掉拟合线性成分，残差再限于 250 Hz–5.2 kHz，只在选中持续音出现；活动 RMS 约低于主唱 32 dB。不是另一条很响的全频复制。 |
| V12 局部丰满 | 选中较弱持续音最多 +0.9 dB，100/180 ms；超过 +0.25 dB 约 19.24 秒。把已有低电平谐波残差提高 1.5 dB；并非给整条主唱加 1.5 dB 饱和驱动。 |
| V12 高频细修 | 6.5 kHz/Q0.9 动态最多 −1.2 dB，8/95 ms；12.5 kHz 高架 +0.4 dB。CORE 配平到约比 V11 高 0.2 LU。 |
| V13 弱字位置 | 只在与伴奏竞争且周期性较明确的片段，做最多 +0.65 dB 缓慢增益，140/250 ms，变化≤1.8 dB/秒；超过 +0.25 dB 约 24.34 秒。整体配平 −0.13 dB，CORE 与 V12 响度只差约 0.01 LU。没有再加主唱 EQ、修音或压缩器。 |

V11 至 V13 保留中央主唱的原调音；只有合成衬层做下述微移调。V13 的六处唱句相关性检查时移均为 0 ms。

### 合成衬层与空间

| 层 | V11 建立的基础 | V12/V13 延续的调整 |
|---|---|---|
| 持续音衬层 | 左 −6、右 +7 音分，保留 formant，延迟 31/49 ms，带宽 420 Hz–6.1 kHz；候选至少 350 ms，避开起音约 60 ms，约 120 ms 渐入/90 ms 渐出；76 段候选、有效展开约 39.59 秒。选中段每声道 RMS 约低于主唱 11.5 dB。 | V12 只把这层 Side 再加 1.6 dB，Mid 不变；V13 衬层样本与 V12 完全相同。它们是合成支撑，不是真实重新演唱的 double。 |
| 句尾回声 | 11 个选定句尾，每句选 444.44 或 666.67 ms；三次重复增益 1/0.24/0.07，逐次变暗、交替声像；主唱活动时最多再下压 6 dB。 | V12 停顿里最多 +0.8 dB；V13 句头额外最多下压 1.5 dB。 |
| 浅扩散尾声 | predelay 40 ms；低/高频名义 T60 0.65/0.45 s，约 600 Hz 高通；低返回量，活动时再下压 3 dB。 | V12 保持；V13 句头额外最多下压 0.6 dB。 |
| 句尾深尾声 | 只由选定句尾发送；predelay 75 ms；低/高频名义 T60 1.55/1.05 s，约 550 Hz 高通；活动时再下压 5 dB。 | V12 停顿里最多 +1.4 dB；V13 句头额外最多下压 2 dB。 |

V13 的句头控制来自 45 处信号规则候选：提前 20 ms 开始，20 ms 进入，保持到从提前起点算约 120 ms，再以约 100 ms 时间常数恢复。这是活动检测，不是歌词识别。

上述效果量由此录音的 RMS 校准，不能把相对 dB 当成任意插件的 Wet 百分比。原 V11 四层中间文件保存于最终总线增益之前；V12 已应用该增益并将其写入各层。复用 V12 层时不能再乘一次 V11 的总线补偿。

### V13 伴奏的最后让位

以 900–1600 Hz Mid 功率比较主唱与伴奏，80 ms 平滑；伴奏/主唱比从 −3 到 +5 dB 映射为 0–1 控制量，再受人声活动约束、35/200 ms 平滑。伴奏 Mid 混入 **1150 Hz/Q1.05/最大 −1.5 dB** 的钟形削减结果，Side 保持，无整条伴奏增益补偿。

最终活跃帧 900–1600 Hz 平均约减少 0.47 dB，较强动作帧约 0.95 dB；40–150 Hz 活跃帧仅约 −0.002 dB。这里让伴奏给弱字留位置，是最终一步的主要构成，不能只拿人声分轨去搭原伴奏而期待完全一样的结果。

### 总线与母带

`CORE + FX + 本版 BEAT → +5.74 dB 总线驱动 → 192 kHz 限幅 → 48 kHz 输出`。

限幅设置：ceiling −1.4 dBFS，attack 5 ms，release 80 ms，关闭自动补偿并补偿延迟。正式 WAV 测得 **−11.55 LUFS / −1.38 dBTP**，MP3 **−11.56 LUFS / −0.98 dBTP**。活动毫秒窗口估计 P95 限幅约 1.84 dB，超过 3 dB 的约 1.50%。这些结果解释制作电平，不是要求所有歌曲都达到同一个数值。

各版本之间沿用母带前分轨，没有把 V11、V12、V13 的完整母带限制器串起来重复压。

详细实际脚本和参数见 [V11](archive/vocal-v11/NOTES.md)、[V12](archive/vocal-v12/NOTES.md)、[V13](archive/vocal-v13/NOTES.md) 及相邻 `build_*.py`、`validation.json`、核验记录。

## 5. 哪些内容能复现，哪些仍依赖旧工作区

| 目标 | 能否只靠正式交付做到 |
|---|---|
| 保留、播放和再次发布这一版声音 | 可以。直接用正式 V1 主文件，并校验 SHA-256；无须重新编码。 |
| 调整主唱、空间与伴奏的相对音量 | 下载本版四个分轨即可；用前述两轨或三轨方式重组。 |
| 根据参数在 Ableton 建立相近的处理思想 | 可以。需按新录音重新定门限、效果量、时间与送轨，不能机械照搬。 |
| 从原干声逐环节完全重渲染 V1 | 不可以只靠便携 ZIP 或历史脚本快照。还缺旧工作区的中间浮点音频、控制输入及最初已打印的插件处理。 |
| 直接运行历史 `build_v13.py` | 不可以只解压 ZIP 就运行。源码保存绝对工作区路径，属于渲染记录，不是自包含发行软件。 |

V13 主渲染至少依赖：

- `/workspace/audio-v12/` 的 `core_mix.f32`、`doubles.f32`、`echo.f32`、`shallow.f32`、`deep.f32`、`controls.npz`、`validation.json`。
- `/workspace/audio-clean/beat_clean.f32`。
- `/workspace/audio-v10-pitch/comparison.npz` 中原 mixed 的音高/周期性控制。
- `/workspace/audio-v13/competition.npz`、`onset_candidates.json`；前者是预先生成的竞争控制，后者是句头候选。
- 比较文件还读取 V12 的 `master.f32`、`vocal.f32`。
- Python、NumPy、SciPy、FFmpeg；若重建 V11 衬层，还需要 FFmpeg 的 Rubber Band 支持。更早版本脚本另有各自输入依赖。

历史快照保留旧版编号、原文判断和当时的绝对路径，便于审计；它们不是重新命名后的独立插件或 `.als` 工程。正式 V1 的版本定义和使用方式以本指南与正式 README 为准。

## 6. 带到下一首歌的经验

1. 先建立清楚、稳定、音色合意的中央主唱，再决定哪些持续音和句尾需要展开。V1 的丰满度来自选择性支撑与前后关系，不能只用一个常开的加宽旋钮概括。
2. 在完整混音中判断主唱位置。局部让伴奏后退、扶起少量弱字，可能比继续全局抬高频或深削低中频更符合这次需求。
3. 空间随句子变化：句头让位、持续音支撑、句尾延伸。FX 推子只控制新制作层，CORE 中的旧空间仍在。
4. 给后续实验保留等响对照和不变的基准。下一次从正式 V1 分支继续；有新理由再改，不自动重复整条历史处理链。
5. 数值检查保障格式、电平、时间和路由；用户试听决定这次审美方向是否成功。此次用户已明确认可 V13，因此它被锁定为 V1；这并不把每条分析假设变成唯一的声学诊断。
