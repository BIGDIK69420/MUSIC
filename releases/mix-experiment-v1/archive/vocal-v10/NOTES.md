# V10：从原始干声重建

这版针对持续的浑浊、盒子感和“像手机录的”质感，重新建立人声处理链。旧 mixed vocal 不再作为音频混入成品；它只为本人的修音走向提供参考。伴奏沿用 V9 的清理版，方便判断换用干声后有什么不同。

## 先听什么

| 文件 | 内容 |
|---|---|
| `MUSIC_v10_REBUILD.mp3` / `.wav` | 完整混音，约 3:34，−12.11 LUFS |
| `MUSIC_v10_COMPARE.mp3` | V9 → V10 的等响整曲片段，再接 V9 → V10 的等响独奏人声 |
| `MUSIC_v10_VOCAL.wav` | 母带处理前的人声，含本次新增的少量混响和延迟 |
| `MUSIC_v10_VOCAL_CORE.wav` | 已修音、EQ、压缩的人声主体，关闭本次新增混响和延迟；**不是未经处理的原始干声** |

比较文件共 53.5 秒：0:00–0:16 为 V9 混音；0:16.5–0:32.5 为 V10 混音；0:33–0:43 为 V9 独奏人声；0:43.5–0:53.5 为 V10 独奏人声。两段混音都约 −16 LUFS，两段独奏都约 −20 LUFS。使用相同播放音量即可。

所有 WAV 均为 48 kHz / 24-bit PCM、双声道，214.27375 秒，从工程 0:00 对齐。CORE 的左右声道相同。导回 Ableton 时关闭 Warp，不要把 CORE 和 VOCAL 叠加，它们包含同一主唱。VOCAL 与 V9 文件夹里的 `MUSIC_v9_BEAT.wav` 在 0 dB 推子相加得到母带前混音；成品另有母带增益与限幅。

## 这次找到了什么

原始干声没有电话那种 3–4 kHz 的硬性频宽截止。“像手机”不能直接归因于采样率或 MP3 编码。更有用的发现是：旧 wet 在句间保留的中低频声音，相对自身唱句电平显著高于 dry。原始 dry 与旧 wet 的 300–600 Hz 静段／唱句能量比分别约 −44.1、−25.7 dB，差约 18.4 dB。这些残留可能包含旧混响、延迟、呼吸、底噪及增益处理的影响，不能仅凭录音把它们全部叫作房间反射。

因此本次不再试图只用固定 EQ 逆转整条旧链，而是从干声重建。最终 V10 的句间中低频残留相对唱句，较 V9 大约降低 12–14 dB；具体掩码与分频数值见 `final_quality.json`。这不是“整首浑浊降低 14 dB”，也不是已经测出了真实混响时间。

初版重建的高频较 V9 少很多，存在发闷风险。结合已有《1 Call》估计人声的两个片段，我在最终主版中温和补回了 presence：3.3 kHz 的增益增加 2 dB、6.5 kHz 高架增加 1 dB。没有按参考频谱差额机械补上 5–10 dB，也没有把参考歌的任何音频加入成品。最终音色仍比 V9 少一些高频增强；主观是否更干净需实际试听。

## 本次实际 vocal chain

这是本次文件用到的设置，可以用现有 Ableton、Pro-Q、Pro-C、Pro-DS 和空间效果实现相近思路。阈值和补偿增益取决于输入电平，不能把它当作适用于所有录音的固定 preset。

1. **保守修复**：UVR-DeEcho-DeReverb 预测残留后，仅减去预测量的 35%。全曲处理在唱句内的中位电平变化接近 0 dB，主要改变部分较弱尾部；不能说它已经消除了房间或原始盒子感。
2. **修音**：估计本人 dry 与旧 mixed 的可信基频差，再以保留 formant 的 Rubber Band 跟随。校正限制在 ±100 音分内，本次最大约 88.6 音分；不确定位置趋向不校正。没有使用参考歌手的声线模型，也没有凭空指定新调性。若在 Ableton 重做，可先沿用原本正确的 Auto-Tune 调性设置；本次无法等同复原原插件的 Retune/Humanize 参数。
3. **前置清理**：75 Hz 高通，12 dB/oct；100 Hz、Q20、−4 dB 窄削，针对测得的轻微窄带残留。
4. **慢速电平自动化**：用 150 Hz–4.5 kHz 活动能量控制，目标约 −24 dBFS，范围 −4 至 +6 dB，变化速度最多 5 dB/s。静音空隙延续邻近有效句子的电平估计，避免下一句开头被压低。
5. **音色 EQ**：260 Hz / Q0.9 / −1 dB；520 Hz / Q1.1 / −1.5 dB；1.7 kHz / Q0.8 / +1.3 dB；3.3 kHz / Q0.9 / +3.2 dB；6.5 kHz 高架 +3 dB。使用常规最小相位滤波，没有把所有中低频深挖掉。
6. **一只主压缩器**：RMS 检测，2.5:1，threshold 约 −26 dBFS，attack 15 ms，release 110 ms，约 9 dB soft knee，不启用自动补偿。本次约 1.96 dB 中位衰减，P95 约 6.62 dB；强处仍会更多压缩。
7. **一次有限 de-ess**：比较 5–11 kHz 与 1.2–4.5 kHz 能量，仅在高频相对突出时平滑削高架，最大约 3 dB，控制 attack 8 ms / release 75 ms。没有激励器与多次去齿音互相叠加。
8. **句间软衰减**：原干声约 −54 至 −42 dBFS 间渐变，hold 约 120 ms、release 200 ms，最深约 −9.1 dB；不会硬切为零。再匹配人声响度，并用 −5.5 dBFS 的峰值保护捕捉极少数尖峰。
9. **单独发送空间效果**：延迟约 444 / 667 ms，发送带宽 550 Hz–5.5 kHz，唱歌时额外避让 7 dB；短扩散尾声约 0.85 s、predelay 55 ms、带宽 650 Hz–5.5 kHz，唱歌时避让 5 dB。新效果保持低电平，没有持续的微移调双轨。脚本中的 −27/−26 dB 是相对活动主声 RMS 的效果校准量，**不是能直接照抄到任意插件的发送推子值**。
10. **母带**：整体约 −12.1 LUFS，192 kHz 过采样限幅，ceiling −1.4 dBFS、attack 5 ms、release 80 ms，补偿延迟、不自动抬回 0 dBFS。不会为了比 V9 更响而让 A/B 失去意义。

## 已完成的验证与边界

- WAV −12.11 LUFS / −1.40 dBTP；MP3 −12.11 LUFS / −1.15 dBTP。最终母带约 95% 的活动毫秒窗口限幅低于 0.80 dB，超过 3 dB 的约 0.29%。这些是近似增益估计，不是所有失真都能被它识别。
- 回读全部导出：长度、声道、采样率、PCM 位深、有限样本、峰值和各声部相加一致性均通过。比较片段编码后再次测响度。
- 修音源与最终人声做了独立周期和时间对齐检查；可信唱句的音高走向接近旧版，但不保证完全复刻原调音或没有任何移调伪影。
- 专用修复模型不能从单段录音唯一推断麦距、电脑屏幕距离或房间结构，也不能据此把问题归咎于牙齿或发声器官。
- 这里完成的是信号分析、重建与数值检查，没有主观试听能力；不声称已确认达到商业唱片听感。CORE 可帮助比较新增空间效果是否适合，但它仍包含原录音及修复、修音、动态处理的影响，不能单靠它判定录音房间就是原因。

`validation.json`、`export-check.json`、`final_quality.md`、`restored_pitch_alignment.json` 记录本次检查。附带脚本保存实际方法，使用当前云工作区路径及先前生成的控制数据；不是下载后即可运行的独立混音软件。没有上传参考歌、参考分离音频或模型权重。
